# Деплой — VPS + Caddy за 15 минут

> Сценарий: один VPS, докер, домен. Postgres, приложение и Caddy (он сам получает и продлевает TLS-сертификат) поднимаются одним compose-файлом — [docker-compose.prod.yml](../docker-compose.prod.yml). Этого хватает подавляющему большинству MVP; когда перестанет хватать, у вас уже будут деньги на нормальную платформу.

## Предпосылки

- VPS с Linux, 1 ГБ памяти достаточно для старта.
- Установленный Docker с плагином compose (`docker compose version` отвечает).
- Домен, A-запись которого уже указывает на IP этого VPS — без этого Caddy не выпустит сертификат.
- Порты 80 и 443 открыты (проверь firewall провайдера, не только ufw).

## Шаг 1. Код и .env

```bash
git clone https://github.com/Nrect/molot-lite.git /opt/molot-lite
cd /opt/molot-lite
cp .env.example .env
```

Теперь пройди по `.env` чек-листом — каждый пункт обязателен:

- **`JWT_SECRET`** — сгенерируй, не выдумывай: `openssl rand -base64 48`. Короче 32 байт приложение не стартует, и это правильно.
- **`POSTGRES_PASSWORD`** — пароль базы, тоже из `openssl rand`. Прод-compose не поднимется без него (и не должен).
- **`CORS_ORIGINS`** — origin твоего фронта, например `https://app.example.com`. Пусто — браузерный фронт с другого домена работать не будет; это безопасный дефолт, а не поломка.
- **`LOG_FORMAT=json`** — в проде логи читает машина, не человек.
- `DATABASE_URL` можно не трогать: прод-compose переопределяет его сам, подставляя хост `postgres` и твой пароль.

## Шаг 2. Домен в Caddyfile

Открой [deploy/Caddyfile](../deploy/Caddyfile) и замени `example.com` на свой домен. Всё: две строки конфига — это весь reverse proxy вместе с автоматическим TLS.

## Шаг 3. Запуск

```bash
docker compose -f docker-compose.prod.yml up -d --build
```

Первый запуск соберёт образ и выпустит сертификат — пара минут. Проверка:

```bash
curl https://example.com/healthz   # 200
curl https://example.com/readyz    # 200, значит и постгрес жив
```

Миграции применяются при старте приложения сами, отдельного шага нет.

## Шаг 4. Демо-данные (по желанию)

Образ несёт второй бинарь — сидер. Он идемпотентен: повторный запуск увидит уже созданных пользователей и спокойно выйдет.

```bash
docker compose -f docker-compose.prod.yml run --rm --entrypoint /seed app
```

## Шаг 5. Бэкапы в крон

[deploy/backup.sh](../deploy/backup.sh) снимает `pg_dump | gzip` и хранит 14 дней. Добавь в crontab пользователя с правами на докер:

```
0 3 * * * /opt/molot-lite/deploy/backup.sh
```

Раз в месяц проверяй, что из свежего дампа реально восстанавливается база — бэкап, который ни разу не разворачивали, это лотерейный билет, а не бэкап.

## Шаг 6 — обязательный. Реальный IP клиента за прокси

Приложение за Caddy видит соединения только от него, поэтому без этого шага rate limit примет весь трафик за одного клиента: первый же всплеск логинов — и 429 получают все пользователи сразу.

В `internal/platform/server/server.go` замени строку

```go
r.Use(middleware.ClientIPFromRemoteAddr)
```

на

```go
r.Use(middleware.ClientIPFromXFFTrustedProxies(1))
```

Единица — это «один доверенный прокси передо мной» (Caddy). Пересобери и перезапусти. Почему это не дефолт: без прокси доверять заголовку `X-Forwarded-For` нельзя — его пишет клиент, и любой бот представился бы чужим IP.

## Обновление версии

```bash
cd /opt/molot-lite
git pull
docker compose -f docker-compose.prod.yml up -d --build
```

Compose пересоберёт образ и перекатит контейнер приложения. Выключение корректное: по SIGTERM `/readyz` сразу отвечает 503 (новый трафик мимо), затем до 10 секунд дорабатывают начатые запросы, и только потом процесс выходит — `stop_grace_period: 15s` в compose даёт этому запас. Ставки посреди транзакции не теряются.

Одной строкой про Kubernetes: там перед дренажом добавь `preStop`-sleep на пару секунд — снятие пода с эндпоинтов в k8s асинхронное, и без паузы часть трафика прилетает в уже гасящийся под.

## Куда смотреть, если что-то не так

| Симптом | Команда |
|---|---|
| Что вообще запущено | `docker compose -f docker-compose.prod.yml ps` |
| Логи приложения | `docker compose -f docker-compose.prod.yml logs -f app` |
| Сертификат не выпускается | `docker compose -f docker-compose.prod.yml logs caddy` — чаще всего DNS ещё не доехал или закрыт 80-й порт |
| База жива? | `curl https://example.com/readyz` — 503 с текстом `postgres not ready` говорит само за себя |
