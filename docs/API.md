# API — справочник ручек

> Этот файл — источник правды по HTTP-контракту. Исполняемые примеры тех же запросов лежат в [api.http](../api.http): открой его в VS Code с расширением REST Client и пройди цепочку сверху вниз. OpenAPI-спеки здесь сознательно нет — почему, написано в [MVP-RULES.md](MVP-RULES.md), раздел «Чего здесь нет».

## Общие договорённости

**Формат ошибки один на весь сервис.** Любая ошибка — это JSON вида `{"slug": "lot-not-found"}` с подходящим HTTP-статусом. Слаг стабилен: на него можно завязывать логику фронта, текст ошибки из него не сделают другим релизом. Маппинг слага в статус живёт в одном месте (`internal/platform/errs`), поэтому «то 404, то 500 на одно и то же» здесь не бывает.

**X-Request-Id.** Каждый ответ несёт заголовок `X-Request-Id`. Если пользователь принёс скриншот с ошибкой — попроси этот заголовок, по нему в логах найдётся вся история конкретного запроса.

**Аутентификация** — `Authorization: Bearer <JWT>`. Токен выдаёт логин, живёт 24 часа. Просроченный или кривой токен на защищённой ручке — это `401 {"slug":"unauthorized"}`.

**Ошибки, возможные на любой ручке с телом:** `400 invalid-json` (мусор вместо JSON или хвост после него), `400 body-too-large` (тело больше 1 МиБ). На любой ручке вообще: `500 internal-server-error` — детали в логах, наружу не уходят.

**Rate limit.** Регистрация и логин защищены пер-IP лимитом (по умолчанию 2 rps, всплеск 5; настраивается `RATE_LIMIT_RPS`/`RATE_LIMIT_BURST`). Превышение — `429 {"slug":"rate-limited"}`. Лимит живёт в памяти процесса: одна реплика, один счётчик.

**Деньги** везде в минорных единицах (центы, копейки): `5000` при `"currency": "USD"` — это 50 долларов. Так не бывает ошибок округления с плавающей точкой.

## Служебные

| Метод и путь | Auth | Успех | Что значит |
|---|---|---|---|
| `GET /healthz` | — | 200 | Процесс жив. Всегда 200, пока процесс отвечает |
| `GET /readyz` | — | 200 / 503 | Готов принимать трафик. 503 — постгрес не отвечает или идёт graceful shutdown |

## Пользователи

| Метод и путь | Auth | Тело | Успех | Слаги ошибок |
|---|---|---|---|---|
| `POST /api/users` | — | `email`, `password`, `displayName` | 201 `{"id"}` | 400 `invalid-email`, `password-too-short`, `password-too-long`, `display-name-required`; 409 `email-taken`; 429 `rate-limited` |
| `POST /api/users/login` | — | `email`, `password` | 200 `{"token"}` | 401 `invalid-credentials`; 429 `rate-limited` |
| `GET /api/users/me` | Bearer | — | 200 профиль | 401 `unauthorized`; 404 `user-not-found` |

Пароль — от 8 до 72 байт (верхняя граница — честное ограничение bcrypt, длиннее он молча обрезал бы). `invalid-credentials` одинаков для «нет такого email» и «не тот пароль» — по ответу нельзя узнать, зарегистрирован ли адрес.

## Лоты

| Метод и путь | Auth | Тело / параметры | Успех | Слаги ошибок |
|---|---|---|---|---|
| `GET /api/lots` | — | `?page=`, `?pageSize=` (макс. 100), `?q=` поиск по названию | 200 `{items, total, page}` | 400 `invalid-page`, `invalid-page-size` |
| `GET /api/lots/{id}` | — | — | 200 лот | 400 `invalid-lot-id`; 404 `lot-not-found` |
| `POST /api/lots` | Bearer | `title`, `description`, `startPriceMinor`, `currency`, `endsAt` | 201 `{"id"}` | 400 `title-required`, `title-too-long`, `invalid-currency`, `invalid-price`, `ends-at-not-future`; 401 `unauthorized`, `unknown-user` |
| `PATCH /api/lots/{id}` | Bearer | любое подмножество полей создания | 200 лот | 400 как у создания + `invalid-lot-id`; 401 `unauthorized`; 403 `not-owner`; 404 `lot-not-found`; 409 `lot-has-bids` |
| `DELETE /api/lots/{id}` | Bearer | — | 204 | 400 `invalid-lot-id`; 401 `unauthorized`; 403 `not-owner`; 404 `lot-not-found`; 409 `lot-has-bids` |

Листинг показывает только активные лоты (срок не вышел), ближайшие к закрытию первыми; конкретный лот по id отдаётся и после закрытия. Правка и удаление — только владельцу и только пока нет ставок: лот со ставками заморожен (`lot-has-bids`), иначе владелец мог бы переписать условия под уже сделанные ставки.

## Ставки

| Метод и путь | Auth | Тело / параметры | Успех | Слаги ошибок |
|---|---|---|---|---|
| `GET /api/lots/{id}/bids` | — | `?page=`, `?pageSize=` | 200 `{items, total, page}` | 400 `invalid-lot-id`, `invalid-page`, `invalid-page-size` |
| `POST /api/lots/{id}/bids` | Bearer | `amountMinor` | 201 ставка | 400 `invalid-lot-id`, `invalid-amount`; 401 `unauthorized`; 403 `owner-cannot-bid`; 404 `lot-not-found`; 409 `lot-closed`, `bid-too-low` |

Ставка обязана строго перебить текущую цену: равная — это `bid-too-low`. Конкурентные ставки сериализуются блокировкой строки лота, из N одновременных одинаковых ставок выигрывает ровно одна — остальные получают `bid-too-low`, и это корректное поведение, а не гонка. История — новые сверху.

## Если фронту понадобится спека

Пока потребитель API — человек с этим файлом и api.http, их достаточно. Триггер взросления: внешняя команда или кодогенерация клиента. Тогда заводи OpenAPI по рецепту старшего шаблона [Molot](https://github.com/Nrect/molot) — а до того момента источник правды здесь.
